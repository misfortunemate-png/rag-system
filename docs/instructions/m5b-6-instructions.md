# 規程エージェント M5b-6作業指示書（空答対処・M5bクローズ）

作成日: 2026-08-16 ／ PM: クリーデ ／ M5b最終フェーズ
位置づけ: M5b-5検収で残存したdeepseek-flash空答問題の対処と、topk既定値の確定。本フェーズ完了でM5bをクローズする。

## 背景

M5b-5検収でtopk10構成のcd-02・cd-05がans_len=0（空答）、topk5構成でもcd-06が2回中1回空答。いずれも検索到達済み（ret>0）にもかかわらずコンポーザーが出力を生成しない、deepseek-flash固有の確率的障害。M5b-5の変更に起因しない既存の問題だが、実運用で回答が空になるのは許容できない。

## 作業項目

### W-1: コンポーザーの空答リトライ（1回）

agent.pyのコンポーザー呼び出し箇所に以下のガードを追加する:

1. コンポーザーの応答テキストが空文字列またはホワイトスペースのみの場合、**同一入力で1回だけリトライ**する
2. リトライ時のLLM呼び出しコストも合計に加算する（P-9）
3. トレース/ログに `composer_retry: true` を記録する
4. リトライ後も空の場合は、以下の定型文を返す:

```
回答の生成に失敗しました。同じ質問をもう一度お試しください。
```

この定型文はLLM生成ではなくハードコードとする（追加のLLMコストを発生させない）。

### W-2: topk既定値の変更

config.pyの `top_k` 既定値を **5** に変更する（現行値を確認の上、5でなければ変更）。

topk5を既定とする根拠:
- retはtopk10と同水準（0.79 vs 0.85）
- 空答の再現率がtopk10より低い
- コストが低い（$0.076 vs $0.088）
- topk10はUI/APIからの明示指定で引き続き利用可能

### W-3: 検証

- eval/questions_crossdomain.jsonl をtopk5（既定）で1回実行する
- 受入基準: 空答 0問、瞬間死 0問、全面拒否 0問
- M5b-5 topk5_r1との比較表を作成（ret/cit/空答の有無）
- 回帰eval（questions.jsonl 10問）を既定設定で実行、全問回答確認

### W-4: _STATUS.md・CLAUDE.md更新

- _STATUS.mdのバージョンをM5b完了に更新

- 次マイルストーン: M5c（ローカルMCPサーバー化）を予告
