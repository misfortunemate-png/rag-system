# Web照合ドメイン調査依頼

依頼日: 2026-08-16 ／ 依頼元: クリーデ（PM）
用途: rag-systemのWeb照合機能（M6）で使用する三層格付けドメインリストの整備
成果物の格納先: rag-system リポジトリ data/web_tiers.yaml

---

## 背景

rag-system（規程エージェント）は所蔵文書から回答を生成するが、所蔵にない規範についてはWebで補完情報を取得する機能（M6）を実装中。取得したWebページの信頼度を機械的に判定するため、ドメイン単位の三層格付けリストが必要。

## 調査対象分野

所蔵文書の分野に対応する以下の領域。すべてを網羅する必要はなく、見つかったものから随時追加する。

- 電気設備（配線・照明・受変電・通信）
- 消防設備（自動火災報知・屋内消火栓・スプリンクラー・誘導灯）
- 建築一般（構造・内装・外装・防水・断熱）
- 機械設備（空調・換気・給排水・衛生器具）
- 法令・基準（建築基準法・消防法・バリアフリー法・省エネ法・労安法）
- 設計・積算
- 塗装・防食

## 三層の定義

| 層 | 定義 | 信頼度 | RAG上の扱い |
|---|---|---|---|
| tier_1 | 官公庁・法令DB・JIS・業界団体・メーカー公式 | 高 | 根拠として引用可 |
| tier_2 | 商社・技術解説サイト・専門メディア | 中 | 引用可・突合推奨 |
| tier_3 | 上記に該当しないすべて | 低 | 参考情報のみ・根拠引用不可 |

tier_3はリストに列挙しない（tier_1・tier_2に該当しなければ自動的にtier_3）。

## 各層に含まれうるサイトの例（調査の起点）

### tier_1 候補
- 官公庁: 国土交通省(mlit.go.jp)、総務省消防庁(fdma.go.jp)、経済産業省(meti.go.jp)、厚生労働省(mhlw.go.jp)、環境省(env.go.jp)
- 法令DB: e-Gov法令検索(elaws.e-gov.go.jp)、裁判所(courts.go.jp)
- JIS: jisc.go.jp、kikakurui.com（JIS無料閲覧）
- 業界団体: 日本電設工業協会(jeca.or.jp)、日本空調衛生工事業協会(nihon-kucho.or.jp)、建築業協会、日本消防設備安全センター(fesc.or.jp)等
- メーカー公式: パナソニック電工、東芝ライテック、三菱電機、ダイキン、TOTO、LIXIL、能美防災、ホーチキ等

### tier_2 候補
- 商社・通販: ミスミ(misumi.co.jp)、モノタロウ(monotaro.com)、オレンジブック(orangebook.com)
- 技術解説: 電気設備の知識と技術、建築設備フォーラム、設備と管理
- 専門メディア: 日経xTECH、建設通信新聞、電気新聞

## 成果物フォーマット

成果物は以下のYAML形式で提出する。rag-systemの data/web_tiers.yaml にそのままマージできる書式。

```yaml
# Web照合 三層格付けドメインリスト
# 判定ルール: URLのドメイン末尾一致（例: "go.jp" は sub.example.go.jp にも該当）
# tier_3は列挙しない（tier_1・tier_2に該当しなければtier_3）

tier_1:
  # ── 官公庁 ──
  - domain: "go.jp"
    note: "日本政府機関（包括）"
  - domain: "mlit.go.jp"
    note: "国土交通省"
  # ...

  # ── 法令DB ──
  - domain: "elaws.e-gov.go.jp"
    note: "e-Gov法令検索"
  # ...

  # ── JIS・規格 ──
  - domain: "jisc.go.jp"
    note: "日本産業標準調査会"
  # ...

  # ── 業界団体 ──
  - domain: "jeca.or.jp"
    note: "日本電設工業協会"
  # ...

  # ── メーカー公式 ──
  - domain: "panasonic.biz"
    note: "パナソニック電設資材"
  # ...

tier_2:
  # ── 商社・通販 ──
  - domain: "misumi.co.jp"
    note: "ミスミ"
  # ...

  # ── 技術解説 ──
  - domain: "example.com"
    note: "○○技術解説サイト"
  # ...
```

### フォーマット規則

- 各エントリは `domain` と `note` の2フィールド
- `domain`: 末尾一致で判定されるドメイン文字列。サブドメインを含めたい場合はより具体的に書く（例: `panasonic.biz` はすべてのサブドメインに該当、`www2.panasonic.biz` は特定サブドメインのみ）
- `note`: そのドメインが何か。日本語で簡潔に。RAGは読まない（人間とPMの参照用）
- go.jpのような包括ドメインと個別ドメイン（mlit.go.jp）が重複してもよい（末尾一致なのでgo.jpが包括する）。ただし個別に書く場合はnoteで区別する理由があること（例: 検索精度を上げるためにgo.jp内の特定サイトを明示）
- 分野ごとにコメント行で区切る

### 提出方法

- YAMLファイルとして提出（ファイル名は任意）
- 随時追加可。一度に完成させる必要はない。見つかったものから提出し、PMがweb_tiers.yamlにマージする
