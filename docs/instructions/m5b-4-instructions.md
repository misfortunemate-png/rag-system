## 背景

M5b-3のクロスドメインevalで、アドバイザーのシステムプロンプトが「電気設備工事編」の単一文書時代のまま陳腐化しており、8問中5問が検索実施前に守備範囲外裁定で即死（loops=1）、cd-02は検索全成功後にスタール検知アドバイザーの裁定で引用ゼロとなった。プロダクション利用でも電気以外の質問が全面拒否される状態にある。

分析の結果、問題はプロンプトの陳腐化だけでなく構造にもある:

1. 守備範囲を裁定するアドバイザーが、唯一scope_text（所蔵リスト）を受け取っていない
2. 収集チャンクをID列のみで渡しており、素材の充足を中身を見ずに判断させている
3. 裁定が二値（続行／全面放棄）で、「部分的に答えられる」の出口がない
4. out_of_scope裁定時、コンポーザーに「守備範囲外宣言を生成せよ」と命じており、収集済み素材が捨てられる
5. スタール検知が「進捗ゼロの連続」と「検索回数の多さ」を混同しており、順調な多検索が難航と誤認される

本フェーズの設計判断はすべて docs/answer-principles-v1.md から逆算する。特に「検索前の守備範囲外裁定は原理的に不可能」（§3）と「回答の標準形＝三部構成」（§4）が改修の軸である。

## 作業範囲

- **何を**: アドバイザー・コンポーザー・プランナーのプロンプトと構造の改修、スタール検知条件の修正、クロスドメインevalの再実行
- **なぜ**: 回答原則（answer-principles-v1.md）に実装を一致させるため
- **どこで**: rag-system リポジトリ（src/agent.py 中心）
- **触らない**: 検索層（RRF重み・リランカー・BM25・ingest）は本フェーズのスコープ外

## 作業項目

### W-1: アドバイザーへの情報供給の改修（構造）

- `_run_advisor` に scope_text を渡す（他役と同じ `_build_scope_docs_text` の出力をシステムプロンプトに合成）
- 収集チャンクの提示を「ID列のみ」から「chunk_id＋階層見出し（hierarchy/heading）＋本文先頭120字程度」に変更する
- トークンガード（P-9）: チャンク提示部の合計が上限（目安8,000字）を超える場合、超過分はchunk_id＋見出しのみに落とす。アドバイザー入力の概算サイズをログに記録する

### W-2: アドバイザープロンプトの全面改稿

- 自己定義を所蔵ベースに改める。「電気設備工事編」「当文書」「本仕様書」等の単一文書表現を一掃する。具体的な分野名・文書名・質問パターン（「〜してはならない部屋は」等）の焼き込みは禁止（answer-principles-v1.md §2）
- 裁定選択肢を再定義する:
  - **(a) replan**: まだ試していない検索軸があり、新クエリを提示して実行ループを続行する
  - **(b) conclude**: 所蔵からの追加取得は見込み薄と判断し、収集済み素材で結論の編纂に移る。このとき「所蔵に不足していると思われる規範領域」の所見（一〜二文）を必ず添える
- **out_of_scope（全面拒否）の出口を廃止する**
- 旧131-134行の即時裁定ブロック（検索実績なしでの守備範囲外裁定指示）を削除する

### W-3: プレループアドバイザーの廃止（構造）

検索前の守備範囲外裁定は原理的に不可能（answer-principles-v1.md §3）であり、プレループアドバイザーの存在理由が消滅したため廃止する。

- プランナー出力から `advisor_recommended` フィールドを削除（W-6と連動）
- pre-loop発火経路（`advisor_trigger_planner`・`advisor_trigger_always` によるプレループ呼び出し）をコードごと削除する
- スタール検知（mid-loop）とpost-loop（未決着時）のアドバイザーは存続する

### W-4: スタール検知条件の修正（決定的コード）

- `stall_hit` を `consecutive_empty >= advisor_k` のみに改める
- `total_search_calls >= search_budget` は「難航」ではなく「予算到達」として別扱いにする: アドバイザーを呼ばず、ループを打ち切って収集済み素材のままコンポーザーへ進む。トレースに `budget_stop` として記録する（P-9: 予算到達時に追加のLLM呼び出しをしない）

### W-5: コンポーザーの改修

- 厳守事項を answer-principles-v1.md §4（三部構成）・§5（文体規律）に基づき全面改稿する。要点:
  - 所蔵に根拠がある部分はチャンク引用付きで回答する
  - 根拠がない部分は「所蔵文書に特段の規定がない」形式で明示し、あるべき規範領域を名指し、参照先の名称・検索キーワード等の調査の手がかりを添える
  - 法規の一般原則・物理法則からの推論は「推論」ラベルを付して提示してよい。裏取りのない断定はしない
  - もっともらしい条番号での穴埋め禁止（不変）
  - 謝罪表現・「無関係」・全面拒否・「専門家にご相談ください」の禁止
- 「本文書には該当規定が見当たらない」等の単数形表現、「（内線規程・電技解釈等）」の電気固有例示を一掃する
- advisor conclude時のユーザーメッセージを改稿する: 「守備範囲外宣言を生成してください」を廃止し、「アドバイザー所見: {reason}（不足領域: {所見}）。収集済み素材から言えることを回答し、不足は三部構成の形式で明示すること」に改める。アドバイザーの裁定は命令ではなく所見として渡す
- 引用の出力形式（<!-- CITATIONS -->二部形式）は変更しない

### W-6: プランナーの更新

- 自己定義を所蔵ベースに改める（「建築工事仕様書の検索計画専門家」→ scope_textに列挙された所蔵文書群を対象とする検索計画係）
- ターゲット例の電気錨（表1.1.1「電線類」）を分野中立の例示に差し替える
- `advisor_recommended` の出力を削除（W-3連動）
- `relevant_domains`（R-10のdomain絞り込み）は現状のまま維持する

### W-7: クロスドメインeval再実行

- eval/questions_crossdomain.jsonl（改変禁止・M5b-3と同一）の10問を再実行する
- 二構成のA/B: 既定 `top_k=5` と `top_k=10` の両方で実行し、M5b-3で判明した検索段ギャップ（precheck top-20ヒット・エージェントtop-5ミス）への効果を計測する（rerank無効のまま・設定変更のみ・検索層のコード改修はしない）
- 回帰: eval/questions.jsonl（既存10問）も再実行し、合格率がM5b時点を維持していることを確認する（プロンプト変更の副作用検査）
- 記録: A部 doc_recall / retrieval_doc_recall、loops、全面拒否回答の有無、各問コスト（P-9）
- B部（cd-09/cd-10）: 回答全文を提出。合否判定はPM＋発注者（判定基準は三部構成・文体規律への準拠）

## 禁止事項

- eval/questions_crossdomain.jsonl・questions.jsonl・questions_m5b.jsonl を改変しない
- プロンプトに具体的な文書名・分野名・質問パターンを焼き込まない（所蔵はscope_textの動的合成で参照する）
- 検索層（RRF重み・リランカー・BM25・ingest・チャンキング）を改修しない（top_k設定値の変更のみ可）
- B部の合否を自動判定しない
