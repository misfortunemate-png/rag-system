## 2. 技術的問題：アドバイザープロンプトの陳腐化

### 問題の所在

[github/rag-system/src/agent.py](rag-system/src/agent.py) 113行目：

```
あなたは公共建築工事標準仕様書（電気設備工事編）の検索アドバイザーです。
```

コーパスはM5b-1で72文書・建築/電気/機械/消防/衛生/法令等の多分野に拡張済み。しかしアドバイザーのシステムプロンプトは旧来の「電気設備工事編専門」のまま更新されていない。

### 障害の連鎖

1. プランナーがクロスドメイン質問を見て `advisor_recommended: true` を出力
2. プレループアドバイザーが**検索実施前**に起動
3. アドバイザーは「電気設備工事編の範囲外」と判断し `out_of_scope` を裁定
4. `pre_loop_skip = True` → 実行ループが完全スキップ（検索ゼロ）
5. コンポーザーが「守備範囲外宣言を生成してください」を受け取り全面拒否回答を生成

131行目の指示も問題を増幅している：

```
検索実績なし（トレース空）でのプレループ発動時:
「まだ検索していないから再計画」は誤り。即座に守備範囲外を裁定せよ。
```

多分野コーパスにおいて「検索前に即座に守備範囲外」とする指示は不適切。

### cd-02の別パターン

cd-02はループ7回目でスタール検知アドバイザーが発動し `out_of_scope` を裁定。検索段では全expected_docs取得済み（retrieval=1.00）にもかかわらず、アドバイザー裁定後のコンポーザーが守備範囲外宣言を生成したため引用ゼロ（citation=0.00）となった。

### 影響範囲

本問題はeval限定ではなく、**プロダクション利用でも機械/衛生/電気技術基準等の質問が全面拒否される**状態にある。M5b-2でコーパスを拡張したが、アドバイザーの自己認識が追いついていない。

## 3. 回答品質要望（発注者フィードバック）

cd-10（多機能トイレ改装）の回答に対し、発注者より以下の指摘があった。コンポーザーとアドバイザーのプロンプト改修に反映させるべき内容をPMに提示する。

### 3-1. 謝罪表現の禁止

現状の回答冒頭：「申し訳ございませんが、ご質問の内容は…」

**要望**: 謝罪表現は不要。専門家向けの調べ物係に謝罪は不適切。

### 3-2. 「無関係」ではなく「特段の規定がない」と言うべき

現状：「消防法は無関係」「建築設備設計基準は内部仕様に関する規定を含まない」

**要望**:
- 消防法が掣肘を受けない部屋は存在しない。「消防法にトイレ改装の特段の規定がない」が正確な表現
- 設計基準類に全く規定がないわけではない。断定は虚偽に当たる

### 3-3. 部分回答 + 不足の明示（全面拒否しない）

現状：根拠がないと全面的に回答を拒否し「本文書には該当規定が見当たらない」で終わる

**要望**: 
- コーパス内に根拠がある部分（一般的なトイレ改装に関する仕様）は回答する
- バリアフリー法固有の部分だけ「コーパスに根拠がない」と正直に明示する
- 不足部分については調査の手助けとなる情報（参照先の名称・検索キーワード等）を提示する方向に移行する

### 3-4. 「専門家にご相談ください」の禁止

現状：「専門家（建築士・バリアフリー診断士）にご相談ください」

**要望**: 顧客が専門家（設計者・施工者等）であることを前提にしている。素人向けの丸投げ表現は不適切。

## 4. PM判断が必要な事項

### 4-1. アドバイザープロンプト改修方針

選択肢A（プロンプト更新）：`_ADVISOR_SYSTEM`の「電気設備工事編」を72文書・多分野を反映した記述に更新。プレループでの即時裁定指示を削除し「検索してから判断」に変更。

選択肢C（両方）：プロンプト更新＋設定変更の組み合わせ。

### 4-2. 回答スタイルガイドラインの策定

- 謝罪表現の禁止

- 部分回答優先の原則（全面拒否禁止）
- 「専門家にご相談」表現の禁止

これらをプロンプトに組み込む形・範囲についてPMの裁量を仰ぐ。
